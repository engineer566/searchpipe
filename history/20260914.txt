## 三、修复：自定义充值分位金额直接 400（真 bug）

- **现象/根因**：`billing.html` 自定义金额输入框是 `min=0.01 step=0.01`，但 `payments/creem.py` 与 `payments/dodo.py` 都要求 `amount_cents % 100 == 0`（整美元），非整数美元抛 ValueError → `payments/routes.py` 转 400。**用户输入 $3.50 必定失败**，而页面文案承诺「strictly at $0.005 = 1 credit」。
- **为何测试测不出**：`tests/test_payments.py` 的自定义充值只用 500/100（整美元），且链路测试走 FakeProvider、不经过真实 provider 的 payload 构造。
- **修复（改为按分计价）**：
  - `creem.py`：自定义金额去掉 units，改传 `custom_price=amount_cents`（Creem 支持一次性产品按分覆盖单价）；本地拦 <100 分。
  - `dodo.py`：改传 `product_cart[0].amount=amount_cents`（Dodo 动态定价）。⚠️ 前置条件：该 product 后台必须开启 Pay What You Want，否则 Dodo **忽略 amount 按固定价收款**。
  - `config.py`：新增 `min_recharge_usd=1`（Creem custom_price 硬下限 $1）；`.env.example` 同步。
  - `service.py`：新增 `min_recharge_cents()` + `create_order` 下限校验（provider 无关，两家一致）。
  - `routes.py`：catalog 新增 `min_recharge_amount` 字段（与 max 对称，前端不再硬编码）。
  - `billing.html`：输入框 `min=1`/placeholder `1.00 ~ 500.00`、文案改「$1 – $500」、JS 加 `MIN_AMOUNT` 下限分支。
- **对 live Creem 的实测依据**：`custom_price=350, units=1` → 200 且回显 `custom_price:350`；`custom_price=50` → 400 `custom_price must not be less than 100`。
- **测试**：`tests/test_payment_webhooks.py` 新增 4 个 provider payload 单测（捕获 httpx 实际发出的 JSON：Creem 传 custom_price 且无 units、<$1 本地拒绝、订阅档走映射不带 custom_price、Dodo cart amount）；`tests/test_payments.py` 新增分位金额链路测试 + 下限校验 + catalog min 断言。

## 四、坑（重要）

1. **Creem 建一次性产品不能传 `billing_period="once"`** —— 会被判为 recurring 并报 400「billing_period required for payment_type of recurring」。一次性产品必须**省略**该字段（读回来才是 `once`）。本次 3 个充值档首轮全因此失败。
2. `abandoned_cart_recovery_enabled` 只在 `POST /v1/products`（创建）可用；`PATCH /v1/products/{id}` 传该字段报「property ... should not exist」→ 只能在 Creem 后台 UI 开。
3. `custom_price` 硬下限 100 分（$1）；product price 下限同为 100 分（只允许 0=免费 或 ≥100）→ 做不出 $0.01 产品，**$1 是平台级下限**。
4. webhook signing secret 与 API Key 都无法经 API 读取（根本没有 webhook 接口），只能后台复制。
5. live Key 打 `test-api.creem.io` 返回 401 → 无法用测试环境验证生产 Key。
