# SearchPipe 出海迁移分析（面向海外用户）

> 写入：2026-09-14 · 类型：决策分析文档
> 背景：国内合规成本过高，决定将 searchpipe.tech 转为面向海外用户；中文资源整体备份保留，待合规完成后可能重启国内版。主体现状：个人；未来注册主体也是**国内个体工商户**（不注册境外公司）。

## 〇、最终决策记录（ADR，2026-09-14 定稿）

**决策：主航道出海，面向海外用户；国内版封存（不删、不推、不收费）。**

### 被否决的备选：国内灰色先行（保留虎皮椒微信收款，做大再补合规）

否决理由（决定性）：

1. **主体天花板**：收费信息服务的法定门槛是**经营性 ICP 许可证**（要求依法设立的内资公司、注册资本 ≥100 万），生成式 AI 服务备案/登记实践上同样要求公司主体。**个体工商户解决不了 AI 服务合规**——"先灰后补合规"的最后一步在主体约束下是断的，该路径的真实形态是"一直灰着，做到被关停/被举报/被迫转型为止"。
2. **结构性矛盾**：灰色模式下每个增长动作（知乎/公众号公域推广）都在放大"被看见"的概率，而被看见正是该模式的终止条件——**路径一的成功会亲手杀死路径一**。
3. **风险性质不对称**：国内路径的下线是法律/资金风险（虎皮椒冻卡跑路、通道封禁、关停），悬崖式、不可逆、随规模单调递增；出海路径的下线是商业风险（推广难、竞争强），可迭代、可止损。
4. **经济性**：国内 dev tool 付费率极低，定价只能走量（¥0.03/积分）；海外同等工作量客单价高一个量级（$5–20/月档）。

### 中文资产处置共识

- `china-archive` 分支 + tag 封存全部中文资源；生产 DB dump 与 `.env` 本地加密留存。
- 国内版**不主动推广、不开放充值**；将来若改变主体策略（注册公司并完成合规）可随时重启。
- 出海弱点应对：推广走 MCP 目录站（mcp.so/Smithery/PulseMCP）+ HN/Reddit/Product Hunt + Google SEO 长尾；差异化打价格（自托管 SearXNG 边际成本低）、MCP-first 体验、"可搜中文互联网的 search API"利基；支付按 5.6 节三阶段走。

### 1.3 支付层的具体改动面（核心工作项）

**好消息：支付层当初就做了 provider 抽象**（`payments/provider.py`，3 个方法：`create_order`/`verify_callback`/`available_channels`），换海外支付商不需要推翻架构：

1. **新增 provider 实现**（约 150–250 行）：海外方案（Stripe/Paddle/Creem 等）全部是"托管收银台 redirect + webhook 回调"模式，与虎皮椒的"下单拿 URL + 异步回调"同构，`create_order → 返回收银台 URL` 的接口形状可直接复用。
2. **回调端点适配**（`payments/routes.py`）：虎皮椒回调是 form 参数（GET/POST 兼容）；海外方案是 JSON POST + 签名头验证（Stripe 的 `Stripe-Signature`、Paddle 的 `Paddle-Signature` 等），回调路由要读 raw body + headers。`handle_callback` 的幂等/发积分编排逻辑可整体保留。
3. **渠道概念泛化**：`PayChannel` 枚举（alipay/wechat）是 Python 层枚举，DB 列是 `String(16)` 无约束——**加 "card"/"paypal" 渠道不需要数据库迁移**；`service.py:96-101` 的硬编码渠道名校验要改成按 provider 动态校验。
4. **货币切换 CNY→USD**：
   - 套餐种子：alembic 新迁移——旧 7 档 `is_active=false` 下架 + 新 USD 档入库（如 $5/$10/$20 充值、$4.99/$9.99/$19.99 订阅）；
   - `config.py`：`credit_yuan_rate` → `credit_usd_rate`（或中性命名 `credit_price_rate` + `currency`）；
   - API 响应字段 `price_yuan`/`credit_yuan_rate`（`payments/routes.py`、`billing/routes.py`）→ 改中性字段名（前端同步）；
   - `seo.py` JSON-LD `priceCurrency: "CNY"` → `"USD"`；
   - 模板全部 `¥` → `$`（约 30 处）。
5. **订阅模式选择**：现有"包月订阅"是自己实现的 30 天积分批次（手动续订，不自动扣款）。海外方案可以：
   - **保持现状**（每期手动支付）→ 开发量最小，任何 provider 都能用；
   - **真自动续订**（Stripe/Paddle 原生 subscription）→ 转化率和 MRR 更好，但要处理 webhook 事件流（invoice.paid 等），多 1–2 天工作量。

### 5.4 FAQ：PayPal / 派安盈（Payoneer）为什么不是主通道

这两个常被提起，但它们卡在链路的**不同环节**上，都不能替代"收单"这一环：

```
海外买家刷卡/PayPal 付款
  ↓ ① 收单：谁面向买家收钱（← 这是主通道问题）
MoR（Creem/Dodo，包税，4%–4.5%） 或 收单商（Airwallex，~3%，需个体户）
  ↓ ② 平台结算给你
Wise / Payoneer / 香港账户（中转账户）
  ↓ ③ 结汇回国
支付宝 / 国内银行卡
```

- **PayPal（作为收单方）**：能收但综合摩擦成本最高——中国账户跨境收款 4.4%+固定费、货币转换汇率损耗 3–4%、提现电汇 $35/笔，合计 7%–8%，比 MoR 还贵且不包税；中国**个人**账户订阅功能受限，企业账户才支持 Subscriptions API。注意：**用 MoR 收款时，买家结账页本来就带 PayPal 按钮**——"让海外用户能用 PayPal 付钱"这个需求已被 MoR 覆盖，无需自开 PayPal 商户号。结论：辅助渠道，不做主通道。
- **派安盈 Payoneer**：本质是**收款账户+结汇通道**（第②③环），不是面向个人的信用卡收单工具（第①环）。Payoneer Checkout 独立站收单存在，但面向已有收款记录的电商主体、主要支持香港等主体，不对大陆个人开放，SaaS/虚拟服务风控也严；"请求付款"（发账单收卡，~3%）是 B2B 人工账单场景，无托管收银台/订阅扣款/Webhook，嵌不进 SaaS 自助购买流程。**正确用法：作为 Creem/Dodo/Paddle 提现的回款账户之一**（与 Wise/万里汇同位），和 MoR 是"和"不是"或"。

### 5.5 路线 C：香港 Stripe（规模上来后的升级选项）

- 个人账户路径：大陆护照 + 香港银行账户（虚拟银行如 ZA/Aspire 可线上开），首年成本约 HK$0–2400；费率 3.4% + HK$2.35。
- 公司账户路径：注册香港公司首年约 HK$8k–15k，年维护 HK$5k–10k（年审+审计）。
- 优点：开发者生态最好、订阅能力最强、风控规则透明。**缺点与你的"不注册境外主体"倾向冲突，列为月收入 $5k+ 后的升级路径。**

### 5.6 推荐：分三阶段走

| 阶段 | 时间 | 收款方案 | 动作 |
|---|---|---|---|
| **0. 现在（纯个人）** | 即刻 | **Creem 或 Dodo Payments（MoR）** 主收款；可选 PayPal 个人辅助 | 审核期间同步做代码改造；MoR 包税，零税务负担 |
| **1. 注册个体工商户后** | 1–3 个月内 | 申请 **Airwallex**（或 PingPong/连连）收单作为主通道，费率降到 ~3%，结汇合规顺畅；MoR 保留作备选 | 个体户注册（电商/软件/信息技术服务经营范围）→ Airwallex 开户 → 切 provider 配置 |
| **2. 规模化后** | 月收入 >$5k | 评估香港公司 + Stripe | 费率与生态最优 |

**代码侧含义**：`PaymentProvider` 抽象正好承接这个分阶段策略——第一阶段实现 `CreemProvider`（或 `DodoProvider`），第二阶段加 `AirwallexProvider`，配置切换即可，业务编排（下单/幂等回调/发积分）零改动。海外支付商全是"托管收银台 redirect + JSON webhook 签名验证"，与现有虎皮椒流程同构。

## 六、税务提示（个体工商户收境外收入）

- **增值税**：向境外单位提供完全在境外消费的信息技术/软件服务，可依**财税〔2016〕36 号附件 4** 做跨境应税行为**免征增值税**（需向主管税务机关做免税报告/留存合同与收款凭证）。
- **所得税**：个体工商户按"经营所得"5%–35% 超额累进；境外收款经 Payoneer/银行结汇回国即有流水记录，**应如实申报**（体量小可适用小规模纳税人/定期定额等安排）。
- **结汇**：MoR/收单平台提现到 Payoneer/万里汇后可人民币结汇到国内个人或对公账户；个体工商户也可开立对公外汇账户直接收电汇。
- ⚠️ 以上为一般性信息非税务意见，落地前建议找一位做过跨境电商/SaaS 的代账会计确认本地执行口径。

## 七、结论与行动建议

**总体判断：迁移成本低、路径清晰，值得做。**

1. **基础设施零成本**：生产服本来就在境外（阿里云国际），域名无需备案，SearXNG 境外配置已是默认——"出海"对运维层几乎无感。
2. **代码改造成本约 6–11 个工作日**，集中在两块：支付替换（2–4 天）+ 全站英文化含测试（3–5 天）。商业化内核（积分/订阅/幂等回调）与语言、支付解耦良好，全部保留。
3. **收款是唯一的"外部依赖瓶颈"**：代码可以立刻写，但 MoR 平台审核（1–7 天）和个体工商户注册（如走路线 B）有等待期。**建议先提交 Creem/Dodo 入驻申请，审核等待期同步做代码改造。**
